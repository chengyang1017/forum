# 2026-08-12 笔记语言与分类整合

## 1. 本次修改目标

本次修改从一个很小的问题开始：

```text
页面中存在写死的语言国旗
```

随后逐渐扩展为一次完整的笔记元数据和创建流程整理。

最终涉及：

- 语言库
- NoteModel
- NoteService
- NoteEditorScreen
- AllNotesScreen
- 笔记筛选
- 新建笔记流程
- 共享成员
- 帖子发布
- 翻译保存笔记

---

# 2. 移除写死的语言数据

之前部分语言 UI 使用页面内部写死数据。

例如：

```text
vi -> 🇻🇳
zh -> 🇨🇳
en -> 🇬🇧
```

问题：

```text
语言越来越多
↓
多个页面重复维护
↓
数据容易不一致
```

现在改为：

```text
glyphora_language_core
↓
ForumLanguages.supportedLanguages
↓
页面
```

语言名称、代码和国旗统一从语言系统获取。

---

# 3. Note 新增 languageCode

NoteModel 新增：

```dart
final String? languageCode;
```

该字段可选。

没有语言时：

```text
null
```

而不是空字符串。

---

# 4. Note category 设计确定

讨论过是否给笔记建立自己的分类系统。

最终决定：

```text
不建立 noteCategories
```

笔记直接使用帖子分类：

```text
Note.category
=
Post.category
```

因为笔记本身就是未来内容生产流程的一部分。

---

# 5. category 和 languageCode 独立

确认：

```text
languageCode
```

和：

```text
category
```

不是互相依赖。

合法状态：

```text
都没有
```

```text
只有 languageCode
```

```text
只有 category
```

```text
两个都有
```

sourceType

同时统一清理空字符串。

```text

```

并继续执行：

```text
owner / participant / allowOthersEdit
```

# 9. NoteEditor 更新

NoteEditor 读取：

```dart
_category = note.category;
_languageCode = note.languageCode;
```

用户可以独立修改：

```text
语言
分类
```

---

# 10. 发布帖子流程优化

以前：

```text
笔记
↓
发布
↓
再选择所有帖子信息
```

现在：

```text
笔记
↓
如果已经有 category
→ 直接复用

如果没有
→ 发布时选择
→ 保存回 Note
```

语言同理。

因此用户不会重复填写已经设置过的信息。

---

# 11. 翻译保存笔记

翻译结果保存笔记时增加：

```dart
sourceType: 'translation',
sourceId: post.id,
category: post.category,
languageCode: targetLanguageCode,
```

因此翻译笔记天然知道：

```text
来源
分类
语言
```

---

# 12. AllNotesScreen 原问题

语言和分类筛选曾经使用大量平铺选择项。

例如：

```text
全部语言
未指定语言
中文
越南语
English
...

全部分类
未分类
语言学习
编程
AI
...
```

页面顶部非常拥挤。

当语言数量继续增加以后，这种结构无法扩展。

---

# 13. 筛选 UI 重构

最终确定：

```text
语言                  全部语言 >
分类                  全部分类 >
```

点击语言：

```text
弹出语言选择
```

点击分类：

```text
弹出分类选择
```

不用 Tab。

不把选项直接铺在页面。

---

# 14. 联合筛选

筛选逻辑：

```dart
return matchesLanguage &&
    matchesCategory;
```

例如：

```text
越南语
+
语言学习
```

得到：

```text
同时属于越南语和语言学习的笔记
```

# 18. 真正创建时机

弹出配置时：

```text
没有创建 Note
```

用户点击：

```text
创建笔记
```

以后才执行：

```dart
_noteService.createNote(...)
```

因此：

```text
打开配置
↓
关闭
```

不会污染数据库。

---

# 19. 跳过按钮讨论

曾考虑：

```text
跳过
```

后来考虑改为：

```text
跳过并创建
```

最终决定：

```text
完全删除
```

因为三个配置本来就是 optional。

用户什么都不选，再点击：

```text
创建笔记
```

本身就是“跳过配置并创建”。

因此不需要第二个重复按钮。
